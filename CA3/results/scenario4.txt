SCENARIO 4 — Effect of network (replication) delay
==================================================
For each delay we (a) issue an EVENTUAL PUT and measure how long all replicas take to
converge and how many stale reads occur, and (b) issue a STRONG PUT and measure its
latency. Cluster: replica1:8081, replica2:8082, replica3:8083.

---- replication delay = 0 ms ----
  EVENTUAL PUT n=d0 -> replica1 | latency 1.3 ms
    immediate GET n -> replica2: {"error":"key not found","key":"n","served_by":"replica2"} (stale=true)
    convergence across all replicas: 21.8 ms (converged=true)
  STRONG   PUT m=d0 -> replica1 | latency 0.7 ms | resp: {"consistency":"strong","key":"m","quorum":2,"replicas_updated":3,"status":"success","version":1}

---- replication delay = 500 ms ----
  EVENTUAL PUT n=d500 -> replica1 | latency 3.5 ms
    immediate GET n -> replica2: {"error":"key not found","key":"n","served_by":"replica2"} (stale=true)
    convergence across all replicas: 523.7 ms (converged=true)
  STRONG   PUT m=d500 -> replica1 | latency 502.3 ms | resp: {"consistency":"strong","key":"m","quorum":2,"replicas_updated":3,"status":"success","version":1}

---- replication delay = 2000 ms ----
  EVENTUAL PUT n=d2000 -> replica1 | latency 3.0 ms
    immediate GET n -> replica2: {"error":"key not found","key":"n","served_by":"replica2"} (stale=true)
    convergence across all replicas: 2037.3 ms (converged=true)
  STRONG   PUT m=d2000 -> replica1 | latency 2002.5 ms | resp: {"consistency":"strong","key":"m","quorum":2,"replicas_updated":3,"status":"success","version":1}

Summary table (network delay vs. behaviour):
  delay |  eventual PUT |  strong PUT  | convergence | client sees stale?
  ------+---------------+--------------+-------------+-------------------
     0ms|       1.3 ms  |      0.7 ms  |    21.8 ms  | YES (until converged)
   500ms|       3.5 ms  |    502.3 ms  |   523.7 ms  | YES (until converged)
  2000ms|       3.0 ms  |   2002.5 ms  |  2037.3 ms  | YES (until converged)

Observations:
  - Eventual PUT latency stays low and roughly constant regardless of the delay, because
    it returns before replication; the cost is paid later as a longer convergence time.
  - Strong PUT latency grows with the delay, because the client must wait for a majority
    of replicas to acknowledge (each ack pays the artificial delay).
  - Convergence time grows with the delay; during that window a client reading another
    replica can observe a stale value under eventual consistency. Under strong consistency
    the write is not acknowledged until the majority has it, so a read on the coordinator
    (or any replica in the acknowledging majority) does not return a stale value.
